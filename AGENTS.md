# AGENTS.md

Config-driven semantic versioning for git repos. File changes trigger patch bumps on merge; minor/major are manual.

## Key Files

| File | Role |
|------|------|
| `git-semver` | Core Python script — `version`, `check`, `bump`, `bump-all`, `tag` subcommands |
| `release` | CI orchestration — with no subcommand decides bump, publish or nothing (called by the git-cicd `release` job); `bump`/`publish` are called by `version-bump.yml` |
| `install.sh` | Installs git-semver into consumer repos |
| `.vendored/configs/git-semver.json` | Versioning config for this repo (dogfooded) |
| `.vendored/configs/git-cicd.json` | Pull request checks and the `release` job for this repo, run by git-cicd |
| `ci/setup.sh`, `ci/test.sh` | Setup and step of the `test` job |
| `.github/workflows/git-cicd-open.yml` | Generated by `git-cicd generate`; runs the checks on PRs |
| `.github/workflows/git-cicd-merge.yml`, `git-cicd-manual.yml` | Generated by `git-cicd generate`; run the `release` job on merge to `main` and by hand |

## Development

Scripts use Python 3 with no external dependencies. Type annotations are used throughout.

### Running Checks

Pull request checks are git-cicd jobs declared in `.vendored/configs/git-cicd.json`: `test` (pytest with coverage, on the Python floor `requires-python` names in `pyproject.toml`) and `vendor-check` (`.vendored/check`). Run them locally the way CI does:

```bash
.vendored/pkg/git-cicd/git-cicd check --setup   # first time: installs the floor Python and test deps into a venv
.vendored/pkg/git-cicd/git-cicd check           # afterwards
```

`ci/setup.sh` reads the floor from `requires-python` and installs it (with uv when it is missing); no Python version is written in a workflow. After changing the git-cicd config, run `.vendored/pkg/git-cicd/git-cicd generate` and commit the generated `.github/workflows/git-cicd-open.yml`, `git-cicd-merge.yml` and `git-cicd-manual.yml`.

### Releasing

The git-cicd `release` job (`.vendored/configs/git-cicd.json`) runs the root `release` with no subcommand on every merge to `main`: a change to a file in `files` (`.vendored/configs/git-semver.json`) is bumped as a patch, a merged `chore: bump version` commit is tagged and gets a GitHub Release, a `chore: install` commit does nothing. Minor and major bumps are started by hand: Actions tab → **Manual** → run on `main` with `job` = `release` and `inputs` = e.g. `{"bump_type": "minor", "subdirectory": "", "changelog_description": "..."}`. It runs the root `release`, not `.vendored/pkg/git-semver/release`, so a release uses the code on the branch.

To run only the tests: `pytest tests/ -v --cov --cov-report=term-missing` (needs `pytest pytest-cov pyyaml`). Test config is in `pyproject.toml`. Tests cover: patterns, versions, config loading, bump/release, updates, git helpers, changelog, commands, install.

### Conventions

- One commit per logical change
- Vendored files (`.vendored/pkg/`, `.vendored/install`, `.vendored/check`) are managed by git-vendored — do not edit directly
- Config changes go in `.vendored/configs/git-semver.json`
- Workflow files are installed artifacts — do not edit

## Vendor Infrastructure

This repo dogfoods its own tooling: its checks and its release are git-cicd jobs (`.vendored/configs/git-cicd.json`), and the `vendor-check` job blocks unauthorized edits to vendored files on PRs. `version-bump.yml`, `check-vendor.yml` and `dogfood.yml` are removed here; git-dogfood is retired. Vendored tools are updated by running `install-vendored.yml` from the Actions tab.
