# AGENTS.md

Config-driven semantic versioning for git repos. By default file changes trigger patch bumps on merge; with `"bump_on": "pull_request"` (as this repo uses) the pull request bumps and the merge is tagged.

## Key Files

| File | Role |
|------|------|
| `git-semver` | Core Python script — `version`, `check`, `check-bump` (with fixing mode: commits and pushes a missing patch bump), `bump`, `bump-all`, `tag`, `released`, `label`/`unlabel`/`labels` (write and list `git-deps.labels.json` in the working tree; never commit or push) subcommands |
| `release` | CI orchestration — with no subcommand decides bump, publish or nothing, or with `bump_on: pull_request` tags the landed commit (called by the git-cicd `release` job); `bump`/`publish` are called by `version-bump.yml` |
| `install.sh` | Installs git-semver into consumer repos |
| `templates/labels.schema` | JSON Schema of `git-deps.labels.json` (format 1), the labels file `git-semver` reads and writes at a repository's root; the README section "Labels" is the contract |
| `.vendored/configs/git-semver.json` | Versioning config for this repo (dogfooded) |
| `.vendored/configs/git-cicd.json` | Pull request checks (including `version-check`, which declares `CICD_WRITE_TOKEN`), the `release` job and `update-vendored` for this repo, run by git-cicd |
| `ci/setup.sh`, `ci/test.sh` | Setup and step of the `test` job |
| `ci/update-vendored.sh` | Step of the `update-vendored` job: runs `.vendored/install` with the job's inputs |
| `tests/bats/` | bats tests of `install.sh` and the `ci/` scripts |
| `.github/workflows/git-cicd-open.yml` | Generated by `git-cicd generate`; runs the checks on PRs |
| `.github/workflows/git-cicd-merge.yml`, `git-cicd-manual.yml` | Generated by `git-cicd generate`; run the `release` job on merge to `main`, and `release` or `update-vendored` by hand |
| `.github/workflows/git-cicd-cron.yml` | Generated by `git-cicd generate`; runs the `update-vendored` job every Monday |

## Development

Scripts need Python 3.11 or later (`requires-python = ">=3.11"` in `pyproject.toml`, the floor the `test` job runs on) and have no external dependencies. Type annotations are used throughout.

### Running Checks

Pull request checks are git-cicd jobs declared in `.vendored/configs/git-cicd.json`: `test` (pytest under coverage on the Python floor `requires-python` names in `pyproject.toml`, then the bats tests in `tests/bats/`), `vendor-check` (`.vendored/check`) and, on pull requests into `main`, `version-check` (the root `git-semver check-bump`).

Coverage measures `git-semver` and `release` (including runs a test starts as a subprocess) and the job fails when the total or either file is below 99%. A new behaviour of either script needs a test; a line is excluded only when no test can reach it, with a comment on the line saying why. A behaviour of `install.sh` or a `ci/` script needs a bats test. Run them locally the way CI does:

```bash
.vendored/pkg/git-cicd/git-cicd check --setup   # first time: installs the floor Python and test deps into a venv
.vendored/pkg/git-cicd/git-cicd check           # afterwards
```

`ci/setup.sh` reads the floor from `requires-python` and installs it (with uv when it is missing), plus bats-core; no Python version is written in a workflow. After changing the git-cicd config, run `.vendored/pkg/git-cicd/git-cicd generate` and commit the generated `.github/workflows/git-cicd-open.yml`, `git-cicd-merge.yml`, `git-cicd-cron.yml` and `git-cicd-manual.yml`.

### Releasing

This repo bumps the version in the pull request (`"bump_on": "pull_request"` in `.vendored/configs/git-semver.json`). A change to a file in `files` must bump `VERSION` in the same pull request: run `./git-semver bump patch --no-push` (or `minor`/`major`; `--no-push` commits the bump without tagging or pushing) and push the commit. The `version-check` job (`git-semver check-bump`, pull requests into `main` only) fails until the version is higher than `main`'s and prints that command. With `CICD_WRITE_TOKEN` declared on the job (`"secrets": ["CICD_WRITE_TOKEN"]`), `check-bump` pushes the patch bump to the pull request branch itself and the pushed commit's run is the one that passes; this repo's job declares it, so with the secret set the bump is pushed for you (without it, run the manual command). A local `check-bump` (or `git-cicd check`) on an unbumped branch makes that commit in the checkout; pass `--no-fix` to only check. Pull requests into `plan/**` are not checked; the pull request into `main` bumps once.

On every merge to `main` the git-cicd `release` job runs the root `release` with no subcommand: it tags the landed commit with the version it carries, pushes the tag and creates the GitHub Release. It pushes nothing to `main`, creates or moves no `latest` tag (no git-semver path does) and does not look at commit subjects (`chore: bump version`, `chore: install`). A version already tagged at another commit fails the job. A manual run (Actions tab → **Manual**, `job` = `release`) releases the current commit; the job has no inputs, so minor and major bumps are made in a pull request. Both jobs run the root scripts, not `.vendored/pkg/git-semver/`, so they use the code on the branch.

To run only the tests: `ci/test.sh` (after `git-cicd check --setup`), or `coverage run -m pytest tests/ && coverage combine && coverage report` and `bats tests/bats` (needs `pytest`, `coverage>=7.10`, `pyyaml` and bats). Test config is in `pyproject.toml`. The suite removes `CICD_WRITE_TOKEN`, `CICD_READ_TOKEN`, `VENDOR_PAT`, `GH_TOKEN` and `GITHUB_TOKEN` before every test (autouse fixture in `tests/conftest.py`, `sandbox` in `tests/bats/helpers.bash`; `tests/test_token_guard.py` and `tests/bats/guard.bats` fail without it); a test that needs a token sets a fake one. Tests cover: patterns, versions, config loading, bump/release, updates, git helpers, changelog, commands, install.

### Conventions

- One commit per logical change
- Vendored files (`.vendored/pkg/`, `.vendored/install`, `.vendored/check`) are managed by git-vendored — do not edit directly
- Config changes go in `.vendored/configs/git-semver.json`
- Workflow files are installed artifacts — do not edit

## Vendor Infrastructure

This repo dogfoods its own tooling: its checks and its release are git-cicd jobs (`.vendored/configs/git-cicd.json`), and the `vendor-check` job blocks unauthorized edits to vendored files on PRs. `version-bump.yml`, `check-vendor.yml` and `dogfood.yml` are removed here; git-dogfood is retired. Vendored tools are updated by the git-cicd `update-vendored` job (`ci/update-vendored.sh`): every Monday at 09:00 UTC on `main`, or by hand from the Actions tab → **Manual** → run on `main`, pick `update-vendored` in the `job` dropdown and fill its `vendor`, `version` and `private` fields (`private` says the vendor's repository is private and is only needed when adding a new vendor; it does not choose a token). The job declares `"secrets": ["CICD_WRITE_TOKEN", "VENDOR_PAT"]`; its script uses `CICD_WRITE_TOKEN`, then the deprecated `VENDOR_PAT`, then the workflow's token. Sessions never run it or `.vendored/install` themselves.
